## <a id="introduction"></a>🎯 Introduction au .gitignore

Le fichier `.gitignore` est un fichier de configuration essentiel qui permet de spécifier quels fichiers et dossiers Git doit **ignorer** et ne jamais tracker. C'est un mécanisme de filtrage qui empêche certains fichiers d'être ajoutés au dépôt.

> [!info] Pourquoi utiliser .gitignore ?
> 
> - **Éviter la pollution du dépôt** : fichiers temporaires, logs, caches
> - **Sécurité** : ne jamais commiter des mots de passe, clés API, tokens
> - **Performance** : exclure les fichiers volumineux (binaires compilés, dépendances)
> - **Propreté** : ignorer les fichiers spécifiques à l'IDE ou au système d'exploitation

> [!example] Exemples typiques de fichiers à ignorer
> 
> - Fichiers de build : `*.o`, `*.class`, `dist/`, `build/`
> - Dépendances : `node_modules/`, `vendor/`, `.venv/`
> - Fichiers système : `.DS_Store`, `Thumbs.db`, `desktop.ini`
> - Fichiers IDE : `.vscode/`, `.idea/`, `*.swp`
> - Fichiers sensibles : `.env`, `config.local.php`, `secrets.yml`

## <a id="syntaxe-patterns"></a>📝 Syntaxe et patterns

### Règles de base

```bash
# Ligne de commentaire (ignorée par Git)

# Ignorer un fichier spécifique
fichier.txt

# Ignorer tous les fichiers avec une extension
*.log

# Ignorer un dossier (le slash final est optionnel mais recommandé)
logs/
temp/

# Ignorer tous les fichiers d'une extension dans tous les sous-dossiers
**/*.tmp
```

### Patterns avancés

```bash
# Ignorer tous les fichiers .txt SAUF important.txt
*.txt
!important.txt

# Ignorer uniquement à la racine du projet (pas dans les sous-dossiers)
/config.json

# Ignorer dans un dossier spécifique
docs/drafts/

# Ignorer tous les .log dans n'importe quel sous-dossier nommé "logs"
**/logs/*.log

# Ignorer les fichiers commençant par "test"
test*

# Ignorer les fichiers se terminant par "_backup"
*_backup

# Utiliser ? pour un seul caractère
file?.txt  # Ignore file1.txt, fileA.txt mais pas file12.txt

# Utiliser [] pour un ensemble de caractères
[Bb]uild/  # Ignore Build/ et build/
file[0-9].txt  # Ignore file0.txt à file9.txt
```

### Tableau récapitulatif des patterns

|Pattern|Signification|Exemple|Ce qui est ignoré|
|---|---|---|---|
|`*`|N'importe quelle séquence de caractères|`*.log`|Tous les fichiers .log|
|`?`|Un seul caractère|`file?.txt`|file1.txt, fileA.txt|
|`**`|N'importe quel nombre de répertoires|`**/temp`|temp/ à tous les niveaux|
|`[abc]`|Un caractère parmi a, b ou c|`file[123].txt`|file1.txt, file2.txt, file3.txt|
|`[a-z]`|Un caractère dans la plage|`log[0-9].txt`|log0.txt à log9.txt|
|`!`|Négation (ne pas ignorer)|`!important.log`|Exception à une règle|
|`/` au début|Relatif à la racine du repo|`/config.json`|Uniquement à la racine|
|`/` à la fin|Dossier uniquement|`build/`|Le dossier build/|

> [!warning] Ordre d'évaluation des règles Git évalue les règles du `.gitignore` **de haut en bas**. Une règle plus spécifique en bas peut annuler une règle plus générale en haut grâce à `!`.

```bash
# Exemple d'ordre d'évaluation
*.log           # Ignore tous les .log
!important.log  # SAUF important.log
logs/           # Ignore le dossier logs/
!logs/keep.log  # Mais garde logs/keep.log
```

## <a id="global-vs-local"></a>🌍 Fichiers .gitignore globaux vs locaux

### .gitignore local (par projet)

Le fichier `.gitignore` à la racine du projet est **commité** et partagé avec toute l'équipe.

```bash
# Créer un .gitignore local
touch .gitignore

# Éditer et ajouter des règles
echo "node_modules/" >> .gitignore
echo "*.log" >> .gitignore

# Commiter le .gitignore
git add .gitignore
git commit -m "Add .gitignore"
```

> [!tip] Utilisation Utilisez le `.gitignore` local pour ignorer des fichiers **spécifiques au projet** que toute l'équipe doit ignorer (build, dépendances, etc.).

### .gitignore global (système)

Un fichier `.gitignore` global s'applique à **tous vos projets Git** sur votre machine. Il n'est **jamais commité**.

```bash
# Créer un .gitignore global (généralement dans le home directory)
touch ~/.gitignore_global

# Ajouter des règles (fichiers système, IDE personnel)
echo ".DS_Store" >> ~/.gitignore_global
echo "Thumbs.db" >> ~/.gitignore_global
echo ".vscode/" >> ~/.gitignore_global
echo "*.swp" >> ~/.gitignore_global

# Configurer Git pour utiliser ce fichier global
git config --global core.excludesfile ~/.gitignore_global
```

> [!tip] Utilisation Utilisez le `.gitignore` global pour ignorer des fichiers **personnels** liés à votre système d'exploitation ou votre éditeur de code que vous ne voulez jamais commiter dans aucun projet.

### .git/info/exclude (local non-commité)

Il existe aussi un fichier `.git/info/exclude` qui fonctionne comme `.gitignore` mais n'est **jamais commité**. Utile pour des exclusions personnelles dans un projet spécifique.

```bash
# Éditer le fichier exclude
nano .git/info/exclude

# Ajouter des règles personnelles
my-personal-notes.txt
temp-experiments/
```

### Comparaison

|Type|Emplacement|Commité ?|Portée|Usage|
|---|---|---|---|---|
|`.gitignore` local|Racine du projet|✅ Oui|Projet|Règles partagées par l'équipe|
|`.gitignore` global|`~/.gitignore_global`|❌ Non|Tous vos projets|Préférences personnelles système/IDE|
|`.git/info/exclude`|`.git/info/exclude`|❌ Non|Projet|Exclusions personnelles non partagées|

## <a id="templates"></a>📋 Templates .gitignore

### Sources de templates

Plutôt que de créer un `.gitignore` depuis zéro, vous pouvez utiliser des templates pré-configurés.

> [!tip] GitHub Templates Collection GitHub maintient une collection officielle de templates : [github.com/github/gitignore](https://github.com/github/gitignore)

### Utiliser un template depuis GitHub

```bash
# Télécharger un template directement (exemple: Node.js)
curl https://raw.githubusercontent.com/github/gitignore/main/Node.gitignore -o .gitignore

# Télécharger un template Python
curl https://raw.githubusercontent.com/github/gitignore/main/Python.gitignore -o .gitignore
```

**Python**


## <a id="fichiers-trackes"></a>🔄 Ignorer des fichiers déjà trackés

### Le problème

Un fichier déjà **tracké** par Git (c'est-à-dire déjà commité) continuera d'être suivi **même si vous l'ajoutez au .gitignore**.

> [!warning] Comportement important `.gitignore` n'affecte que les fichiers **non-trackés**. Si un fichier est déjà dans l'historique Git, l'ajouter au `.gitignore` ne le supprimera pas automatiquement.

### Solution : git rm --cached

Pour ignorer un fichier déjà tracké, vous devez le **retirer de l'index** Git tout en le conservant localement.

```bash
# Retirer UN fichier de l'index (mais le garder sur le disque)
git rm --cached fichier-sensible.txt

# Retirer un DOSSIER de l'index
git rm --cached -r node_modules/

# Ajouter la règle au .gitignore
echo "fichier-sensible.txt" >> .gitignore
echo "node_modules/" >> .gitignore

# Commiter le changement
git add .gitignore
git commit -m "Remove tracked files now in .gitignore"
```

> [!info] Différence entre rm et rm --cached
> 
> - `git rm fichier.txt` : Supprime le fichier de Git **ET** du disque
> - `git rm --cached fichier.txt` : Supprime le fichier de Git **MAIS** le garde sur le disque

### Cas d'usage typique : fichier .env

```bash
# Situation : vous avez commité un fichier .env par erreur
# 1. Retirer le fichier de l'index
git rm --cached .env

# 2. Ajouter .env au .gitignore
echo ".env" >> .gitignore

# 3. Commiter les changements
git add .gitignore
git commit -m "Remove .env from tracking"

# Le fichier .env reste sur votre disque mais ne sera plus tracké
```

### Nettoyer tout l'index et réappliquer .gitignore

Si vous avez modifié significativement votre `.gitignore` et voulez nettoyer tous les fichiers maintenant ignorés :

```bash
# 1. Retirer tous les fichiers de l'index (mais les garder sur le disque)
git rm -r --cached .

# 2. Ré-ajouter tous les fichiers (respectant le .gitignore)
git add .

# 3. Commiter
git commit -m "Apply .gitignore to all tracked files"
```

> [!warning] Attention avec cette commande Cette opération va créer un commit qui modifie potentiellement beaucoup de fichiers. Assurez-vous d'avoir sauvegardé votre travail et vérifiez les changements avant de commiter.

### Vérifier ce qui est ignoré

```bash
# Voir les fichiers ignorés dans le répertoire actuel
git status --ignored

# Vérifier pourquoi un fichier est ignoré
git check-ignore -v fichier.txt

# Lister tous les fichiers ignorés récursivement
git check-ignore -v **/*
```

## <a id="pieges-pratiques"></a>⚠️ Pièges courants et bonnes pratiques

### Pièges courants

> [!warning] Piège #1 : Espaces dans les noms de fichiers
> 
> ```bash
> # ❌ Incorrect - n'ignore pas "mon fichier.txt"
> mon fichier.txt
> 
> # ✅ Correct - échapper l'espace ou utiliser des guillemets
> mon\ fichier.txt
> "mon fichier.txt"
> ```

> [!warning] Piège #2 : Slash de fin pour les dossiers
> 
> ```bash
> # ⚠️ Ambigu - pourrait ignorer fichier OU dossier nommé "build"
> build
> 
> # ✅ Clair - ignore uniquement le DOSSIER build/
> build/
> ```

> [!warning] Piège #3 : Ordre des règles de négation
> 
> ```bash
> # ❌ Ne fonctionne pas - la négation est AVANT l'exclusion
> !important.log
> *.log
> 
> # ✅ Fonctionne - la négation vient APRÈS
> *.log
> !important.log
> ```

> [!warning] Piège #4 : Négation dans un dossier ignoré
> 
> ```bash
> # ❌ Ne fonctionne PAS - impossible de ré-inclure un fichier dans un dossier ignoré
> logs/
> !logs/important.log
> 
> # ✅ Solution - ignorer le contenu, pas le dossier
> logs/*
> !logs/important.log
> ```

> [!warning] Piège #5 : .gitignore lui-même
> 
> ```bash
> # ❌ N'ignorez JAMAIS le .gitignore (sauf cas très spécifiques)
> # .gitignore
> 
> # Le .gitignore doit être commité pour être partagé
> ```

### Bonnes pratiques

> [!tip] Bonne pratique #1 : Structure du .gitignore Organisez votre `.gitignore` en sections avec des commentaires :
> 
> ```bash
> # ===============================
> # Fichiers système
> # ===============================
> .DS_Store
> Thumbs.db
> 
> # ===============================
> # IDE et éditeurs
> # ===============================
> .vscode/
> .idea/
> *.swp
> 
> # ===============================
> # Dépendances
> # ===============================
> node_modules/
> vendor/
> 
> # ===============================
> # Build et distribution
> # ===============================
> dist/
> build/
> *.o
> 
> # ===============================
> # Fichiers sensibles
> # ===============================
> .env
> .env.local
> secrets.yml
> ```

> [!tip] Bonne pratique #2 : Ignorer tôt Ajoutez le `.gitignore` **dès le début** du projet, avant de commiter quoi que ce soit. Cela évite d'avoir à nettoyer l'historique plus tard.

> [!tip] Bonne pratique #3 : Templates + personnalisation Commencez avec un template, puis adaptez-le à votre projet :
> 
> ```bash
> # 1. Télécharger un template
> curl https://raw.githubusercontent.com/github/gitignore/main/Node.gitignore -o .gitignore
> 
> # 2. Ajouter vos règles spécifiques
> echo "" >> .gitignore
> echo "# Règles spécifiques au projet" >> .gitignore
> echo "data/raw/" >> .gitignore
> echo "experiments/" >> .gitignore
> ```

> [!tip] Bonne pratique #4 : Séparer global et local
> 
> - **Global** : préférences personnelles (IDE, OS)
> - **Local** : règles spécifiques au projet (build, deps)
> 
> Ne forcez pas toute l'équipe à ignorer votre IDE préféré via le `.gitignore` local.

> [!tip] Bonne pratique #5 : Tester les patterns Utilisez `git check-ignore` pour vérifier vos règles :
> 
> ```bash
> # Créer des fichiers de test
> touch test.log test.txt important.log
> 
> # Vérifier ce qui serait ignoré
> git check-ignore -v test.log test.txt important.log
> 
> # Nettoyer
> rm test.log test.txt important.log
> ```

> [!tip] Bonne pratique #6 : Documentation Ajoutez des commentaires dans votre `.gitignore` pour expliquer les règles non évidentes :
> 
> ```bash
> # Ignorer les datasets volumineux (>100MB)
> data/large_dataset.csv
> 
> # Fichiers temporaires générés par notre pipeline de build custom
> .pipeline-cache/
> 
> # Credentials AWS - NE JAMAIS COMMITER
> aws-credentials.json
> ```

### Astuces avancées

> [!tip] Astuce #1 : Pattern de négation pour exceptions
> 
> ```bash
> # Ignorer tous les fichiers de config SAUF le template
> config/*.json
> !config/config.template.json
> ```

> [!tip] Astuce #2 : Ignorer sauf certaines extensions
> 
> ```bash
> # Dans le dossier assets/, ignorer tout sauf les .png
> assets/*
> !assets/*.png
> ```

> [!tip] Astuce #3 : Utiliser des .gitignore dans les sous-dossiers Vous pouvez placer des `.gitignore` dans n'importe quel sous-dossier. Ils s'appliquent à ce dossier et ses enfants.
> 
> ```bash
> project/
> ├── .gitignore          # Règles globales
> ├── tests/
> │   └── .gitignore      # Règles spécifiques aux tests
> └── docs/
>     └── .gitignore      # Règles spécifiques à la doc
> ```

> [!tip] Astuce #4 : Vérifier l'impact avant de commiter
> 
> ```bash
> # Voir ce qui sera commité (en respectant .gitignore)
> git add -n .
> 
> # Voir les fichiers ignorés
> git status --ignored
> ```

> [!tip] Astuce #5 : Forcer l'ajout d'un fichier ignoré (cas exceptionnel)
> 
> ```bash
> # Si vous devez vraiment ajouter un fichier ignoré
> git add -f fichier-ignore.txt
> ```

## 🎓 Résumé

Le `.gitignore` est un outil puissant pour maintenir un dépôt Git propre et sécurisé :

- **Syntaxe flexible** : patterns, wildcards, négations
- **Trois niveaux** : local (partagé), global (personnel), exclude (local personnel)
- **Templates disponibles** : GitHub, gitignore.io pour démarrer rapidement
- **Fichiers déjà trackés** : utiliser `git rm --cached` pour les retirer
- **Organisation** : structure claire, commentaires, séparation par catégories
- **Anticipation** : ajouter le `.gitignore` dès le début du projet

Un bon `.gitignore` est essentiel pour la collaboration et la sécurité de vos projets Git.
