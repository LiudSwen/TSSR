## 🎯 Introduction

Le fichier `.gitattributes` permet de définir des **attributs spécifiques par chemin de fichier** dans votre dépôt Git. Contrairement à `.gitignore` qui détermine quels fichiers ignorer, `.gitattributes` contrôle **comment Git traite certains fichiers**.

> [!info] Pourquoi utiliser .gitattributes ?
> 
> - Garantir une cohérence entre tous les contributeurs (fins de ligne, encodage)
> - Personnaliser le comportement de Git pour certains types de fichiers
> - Améliorer l'affichage des diffs pour des formats spécifiques
> - Marquer explicitement les fichiers binaires pour éviter des problèmes de fusion

### Syntaxe de base

```bash
# Pattern de fichier    attribut=valeur
*.txt                   text
*.jpg                   binary
*.md                    text eol=lf
```

> [!tip] Emplacement Le fichier `.gitattributes` peut être placé :
> 
> - À la racine du dépôt (s'applique à tout le projet)
> - Dans n'importe quel sous-répertoire (s'applique uniquement aux fichiers de ce répertoire et ses sous-répertoires)

## 🔄 Normalisation des fins de ligne

### Pourquoi c'est important

Les systèmes d'exploitation utilisent différentes conventions pour les fins de ligne :

- **Windows** : `CRLF` (Carriage Return + Line Feed : `\r\n`)
- **Unix/Linux/macOS** : `LF` (Line Feed : `\n`)

Sans normalisation, cela peut causer :

- Des diffs montrant que toutes les lignes ont changé alors que seules les fins de ligne ont été modifiées
- Des problèmes d'exécution de scripts
- Une pollution de l'historique Git

### L'attribut `text`

```bash
# Marque un fichier comme texte, Git normalisera les fins de ligne
*.txt text

# Tous les fichiers texte
*.md text
*.css text
*.js text
*.html text
*.json text
*.xml text
*.yaml text
*.yml text
```

> [!info] Comportement de l'attribut `text` Quand un fichier est marqué comme `text` :
> 
> - **Dans le dépôt** : Git stocke toujours avec des fins de ligne `LF`
> - **Dans le working directory** : Git convertit selon la configuration locale (généralement `CRLF` sur Windows, `LF` sur Unix)

### L'attribut `eol` (End Of Line)

L'attribut `eol` permet de **forcer** un type de fin de ligne spécifique :

```bash
# Force LF (Unix) pour tous - recommandé pour la plupart des projets
*.sh text eol=lf
*.bash text eol=lf
Makefile text eol=lf

# Force CRLF (Windows) - rare, mais parfois nécessaire
*.bat text eol=crlf
*.cmd text eol=crlf
*.ps1 text eol=crlf
```

> [!warning] Différence importante
> 
> - `text` seul : Git normalise selon la config locale de l'utilisateur
> - `text eol=lf` : Force LF pour tous, quelle que soit la plateforme
> - `text eol=crlf` : Force CRLF pour tous, quelle que soit la plateforme

### Auto-détection avec `text=auto`

```bash
# Git détermine automatiquement si un fichier est texte ou binaire
* text=auto
```

> [!example] Configuration complète recommandée
> 
> ```bash
> # Auto-détection par défaut
> * text=auto
> 
> # Fichiers qui doivent toujours utiliser LF
> *.sh text eol=lf
> *.bash text eol=lf
> 
> # Fichiers qui doivent toujours utiliser CRLF
> *.bat text eol=crlf
> *.cmd text eol=crlf
> 
> # Fichiers explicitement texte
> *.md text
> *.txt text
> *.json text
> ```

### Désactiver la normalisation

```bash
# -text désactive la normalisation (traité comme binaire pour les fins de ligne)
*.dat -text

# Ou explicitement marquer comme binaire
*.dat binary
```

## 🔧 Filtres et diff personnalisés

### Personnalisation des diffs

Git permet de définir des **drivers de diff personnalisés** pour améliorer l'affichage des différences sur certains types de fichiers.

#### Diff pour les documents Word

```bash
# Dans .gitattributes
*.docx diff=word

# Dans .git/config ou ~/.gitconfig
# [diff "word"]
#     textconv = docx2txt
```

Cela permet de voir les diffs de fichiers Word comme du texte au lieu de binaire.

#### Diff pour les images

```bash
# Dans .gitattributes
*.png diff=exif
*.jpg diff=exif

# Dans .git/config
# [diff "exif"]
#     textconv = exiftool
```

> [!tip] Drivers de diff courants
> 
> |Type de fichier|Driver|Outil requis|
> |---|---|---|
> |PDF|pdf|pdftotext|
> |Word (.docx)|word|docx2txt|
> |Excel|excel|xlsx2csv|
> |Images|exif|exiftool|
> |JSON|json|jq|

#### Diff personnalisé pour JSON

```bash
# Dans .gitattributes
*.json diff=json

# Dans .git/config
# [diff "json"]
#     textconv = "jq --sort-keys ."
```

Cela trie les clés JSON avant de comparer, rendant les diffs plus lisibles.

### Filtres clean/smudge

Les filtres permettent de **transformer le contenu** des fichiers entre le working directory et le dépôt.

```bash
# Dans .gitattributes
*.secret filter=encrypt

# Configuration du filtre dans .git/config
# [filter "encrypt"]
#     clean = openssl enc -aes-256-cbc -salt
#     smudge = openssl enc -d -aes-256-cbc
```

> [!info] Clean vs Smudge
> 
> - **clean** : Transformation appliquée lors du `git add` (working directory → dépôt)
> - **smudge** : Transformation appliquée lors du `git checkout` (dépôt → working directory)

```
Working Directory  →  (clean filter)  →  Git Database
Working Directory  ←  (smudge filter) ←  Git Database
```

> [!example] Cas d'usage des filtres
> 
> - Chiffrement de fichiers sensibles
> - Suppression automatique de métadonnées
> - Expansion/compression de fichiers
> - Normalisation de format
> - Insertion automatique de variables (date, version, etc.)

### L'attribut `diff`

```bash
# Désactive complètement le diff pour certains fichiers
*.min.js -diff
*.min.css -diff

# Utilise un driver de diff spécifique
*.php diff=php
*.py diff=python
```

## 🖼️ Gestion des fichiers binaires

### Marquer les fichiers binaires

```bash
# Marque explicitement comme binaire
*.png binary
*.jpg binary
*.gif binary
*.ico binary
*.pdf binary
*.zip binary
*.exe binary
*.dll binary
*.so binary
*.dylib binary
```

> [!info] Qu'est-ce que l'attribut `binary` ? `binary` est un raccourci équivalent à `-text -diff`, ce qui signifie :
> 
> - Pas de normalisation des fins de ligne
> - Pas de génération de diff (affichera "Binary files differ")

### Fichiers binaires avec tracking LFS

Git LFS (Large File Storage) permet de stocker les gros fichiers binaires efficacement :

```bash
# Marque les fichiers pour Git LFS
*.psd filter=lfs diff=lfs merge=lfs -text
*.ai filter=lfs diff=lfs merge=lfs -text
*.mp4 filter=lfs diff=lfs merge=lfs -text
*.mov filter=lfs diff=lfs merge=lfs -text
```

> [!warning] Git LFS requis Cette configuration nécessite que Git LFS soit installé et initialisé dans le dépôt. Sans LFS, ces attributs ne fonctionneront pas correctement.

### Désactiver les diffs pour les fichiers générés

```bash
# Fichiers minifiés - pas besoin de diff
*.min.js binary
*.min.css binary

# Fichiers de build
dist/* binary
build/* binary

# Fichiers de dépendances
package-lock.json -diff
yarn.lock -diff
```

> [!tip] Pourquoi désactiver les diffs ?
> 
> - Réduit le bruit dans les pull requests
> - Accélère les opérations Git
> - Évite d'afficher des milliers de lignes de code minifié/généré

### Configuration complète pour un projet web

> [!example] Exemple de .gitattributes pour projet web
> 
> ```bash
> # Auto-détection
> * text=auto
> 
> # Fichiers texte
> *.html text eol=lf
> *.css text eol=lf
> *.js text eol=lf
> *.json text eol=lf
> *.md text eol=lf
> *.xml text eol=lf
> *.yaml text eol=lf
> *.yml text eol=lf
> 
> # Scripts shell
> *.sh text eol=lf
> *.bash text eol=lf
> 
> # Images
> *.png binary
> *.jpg binary
> *.jpeg binary
> *.gif binary
> *.ico binary
> *.svg text eol=lf
> 
> # Fonts
> *.woff binary
> *.woff2 binary
> *.ttf binary
> *.eot binary
> 
> # Archives et exécutables
> *.zip binary
> *.tar binary

>

> ```

## ⚠️ Pièges courants

### 1. Modification des attributs sur des fichiers existants

> [!warning] Les attributs ne s'appliquent pas rétroactivement Quand vous ajoutez ou modifiez `.gitattributes`, les fichiers déjà dans Git ne sont **pas automatiquement mis à jour**.

Pour appliquer les nouveaux attributs :

```bash
# Supprime tous les fichiers de l'index (sans les supprimer du disque)
git rm --cached -r .

# Re-ajoute tous les fichiers (applique les nouveaux attributs)
git add .

# Commit les changements
git commit -m "Applique les attributs .gitattributes"
```

### 2. Conflits entre plusieurs .gitattributes

> [!warning] Priorité des règles Si plusieurs fichiers `.gitattributes` existent à différents niveaux :
> 
> - Les règles les plus spécifiques (plus proches du fichier) ont priorité
> - En cas de conflit, la dernière règle définie gagne

### 3. L'attribut text=auto peut surprendre

```bash
# text=auto peut détecter incorrectement certains fichiers
# comme du texte alors qu'ils sont binaires (ou vice-versa)
* text=auto  # Parfois trop agressif
```

> [!tip] Solution Soyez explicite pour les types de fichiers importants :
> 
> ```bash
> * text=auto
> *.jpg binary
> *.png binary
> *.pdf binary
> ```

### 4. Oublier de committer .gitattributes

> [!warning] Important Le fichier `.gitattributes` **doit être commité** dans le dépôt pour que tous les contributeurs bénéficient des mêmes règles. Un `.gitattributes` local uniquement ne sera pas partagé.

### 5. Confusion entre .gitignore et .gitattributes

|`.gitignore`|`.gitattributes`|
|---|---|
|Ignore des fichiers (ne pas tracker)|Contrôle le comportement sur les fichiers trackés|
|Empêche l'ajout au dépôt|N'empêche pas le tracking|
|`*.log` = ne jamais ajouter les .log|`*.log binary` = traite les .log comme binaires|

## ✅ Bonnes pratiques

### 1. Commencer simple

```bash
# Configuration minimale recommandée pour tout projet
* text=auto
```

Cette seule ligne couvre déjà 80% des cas d'usage.

### 2. Être explicite pour les fichiers critiques

```bash
# Soyez explicite pour les fichiers où les fins de ligne comptent
*.sh text eol=lf
*.bat text eol=crlf
Makefile text eol=lf
```

### 3. Documenter les choix non-évidents

```bash
# Traité comme binaire car contient des données encodées
# même si techniquement du texte
*.b64 binary

# Diff désactivé car fichiers générés automatiquement
schema.sql -diff
```

### 4. Organiser par catégories

> [!example] Structure recommandée
> 
> ```bash
> # Auto-détection
> * text=auto
> 
> # ===== Source Code =====
> *.js text eol=lf
> *.css text eol=lf
> *.html text eol=lf
> 
> # ===== Scripts =====
> *.sh text eol=lf
> *.bash text eol=lf
> *.bat text eol=crlf
> 
> # ===== Images =====
> *.jpg binary
> *.png binary
> *.gif binary
> 
> # ===== Archives =====
> *.zip binary
> *.tar binary
> 
> # ===== Generated Files =====
> *.min.js -diff
> package-lock.json -diff
> ```

### 5. Utiliser des templates

> [!tip] Templates par technologie GitHub propose des templates `.gitattributes` pour différentes technologies :
> 
> - Node.js : https://github.com/alexkaratarakis/gitattributes/blob/master/Web.gitattributes
> - Python : https://github.com/alexkaratarakis/gitattributes/blob/master/Python.gitattributes
> - Unity : https://github.com/alexkaratarakis/gitattributes/blob/master/Unity.gitattributes

### 6. Tester les changements

```bash
# Vérifier les attributs appliqués à un fichier
git check-attr -a chemin/vers/fichier.txt

# Exemple de sortie :
# chemin/vers/fichier.txt: text: set
# chemin/vers/fichier.txt: eol: lf
```

### 7. Combiner avec .editorconfig

> [!info] Complémentarité
> 
> - `.gitattributes` : Contrôle le comportement de Git
> - `.editorconfig` : Contrôle le comportement de l'éditeur
> 
> Les deux devraient être cohérents pour garantir une expérience uniforme.

### 8. Priorité aux standards de l'équipe

```bash
# Si votre équipe est principalement sur Windows
# et que les outils nécessitent CRLF
*.txt text eol=crlf

# Documentez ce choix dans le README ou CONTRIBUTING
```

## 🎓 Astuces avancées

### Debugging des attributs

```bash
# Lister tous les attributs d'un fichier
git check-attr -a fichier.txt

# Vérifier un attribut spécifique
git check-attr text fichier.txt

# Vérifier pour tous les fichiers d'un répertoire
git check-attr -a src/**/*.js
```

### Réinitialiser les fins de ligne de tout le dépôt

Si vous venez d'ajouter `.gitattributes` et voulez normaliser tout l'historique :

```bash
# Attention : cela réécrit l'historique !
git add --renormalize .
git commit -m "Normalise les fins de ligne selon .gitattributes"
```

### Attributs personnalisés

Vous pouvez définir vos propres attributs pour des scripts personnalisés :

```bash
# Dans .gitattributes
*.custom custom-attr

# Puis dans vos scripts Git hooks
# git check-attr custom-attr $file
```

**💡 Le fichier `.gitattributes` est un outil puissant pour harmoniser le comportement de Git dans une équipe. Commencez simple avec `* text=auto`, puis ajoutez des règles spécifiques selon vos besoins.**
